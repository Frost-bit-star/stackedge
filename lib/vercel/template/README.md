# Stackedge FRPS deployment

Generated by `stackedge vercel init`. Deploy this directory to Vercel.

## Configuration

`config.json` contains the deployment service ID, bearer token and app name. It is generated locally by Stackedge and is read by `api/gateway.js`, so no Vercel environment variables are required on Hobby hosting.

Environment variables still override `config.json`:

- `STACKEDGE_FRPS_SERVICE_ID`
- `STACKEDGE_FRPS_TOKEN`
- `STACKEDGE_FRPS_APP`
- `STACKEDGE_FRPS_MAX_BODY_SIZE`

Keep this project private: `config.json` contains a live bearer token.

When the app is offline or a relay error occurs, the gateway returns the branded Stackedge error page from `errorpagetempdesign.html`. The page directs visitors to retry and directs owners to report issues or open pull requests at https://github.com/Frost-bit-star/stackedge.

## Runtime check

Run `stackedge vercel probe <app>` on the user's machine after deployment. Vercel functions are isolated; an in-memory tunnel is visible only to the instance holding it. If the probe reports cross-instance routing, this deployment cannot transparently relay public requests. Deploy `server.js` to a long-lived Node runtime instead, or use a Vercel-supported persistent transport.
